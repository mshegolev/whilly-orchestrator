# Product swarm implementation plan

Goal: one product chat, separate feature sessions, strong planning and cheap implementation, versioned specs/approval/budgets, independent verification, controlled MR publication. Existing swarm sessions remain compatible.

## Global Constraints
- PUBLIC repository: neutral examples only; real product registry and secrets remain outside repo.
- No push, merge, deployment or paid model calls during development without an explicitly configured authorized target.
- Existing uncommitted swarm implementation is the baseline; preserve it. Do not commit mixed work.
- Implementers/reviewers use Luna low only, no nested agents. Up to five simultaneous model processes across installed runtime.
- Approval binds feature revision, specification, registry/base SHAs, profiles and budget; mutation invalidates approval.
- Strong models plan/replan, never implement product code. Cheap workers get two attempts then named escalation.
- TDD, unit/integration/browser checks; unsupported setup is named blocked, never silent fallback.

## Task 1: Execution profiles
Owned: whilly/swarm/registry.py, engines.py, profiles.py (new); focused profile/engine tests. Do not edit runtime.py or agent.py.
Add optional registry profiles mapping with names planner-strong,worker-cheap,reviewer-cheap,planner-escalation. Profile fields engine, model, reasoning_effort, max_turns, timeout_seconds, budget_usd. Validate engine, explicit model, positive finite budgets/limits and supported effort. Legacy registry must continue parsing unchanged. Provide resolve_profile(registry, name) -> profile; missing profile raises named validation error, no fallback. EngineConfig gains reasoning_effort optional; build_engine_argv uses configured effort, defaults low for legacy Codex. Profile returns an EngineConfig with explicit model/effort through helper profile_engine(registry,name). Do not allow workers to select planner profiles.
Tests: old registry roundtrip; strong and cheap same engine with distinct models; unknown engine/blank model/invalid bounds; Codex high vs legacy low; no expensive fallback.

## Task 2: Durable product/features API
Owned: whilly/swarm/product.py, product_store.py (new), migrations/031_product_swarm.py, whilly/api/product_swarm.py (new), tests/unit/test_product_swarm*.py, tests/integration/test_product_swarm*.py.
Implement PostgreSQL-backed product chat + features linked to existing swarm session IDs. Constructor ProductService(pool, registry_path). REST router build_product_router(pool,secret,registry_path) under /api/v1/swarm/products; authenticated admin+existing CSRF. Product id 'default' seeded idempotently from registry name; GET /products, GET/POST /products/default/messages; POST /products/default/features {title,intent}; GET /features/{id}; POST /features/{id}/spec {body}; POST /features/{id}/approve {revision,digest}; POST /features/{id}/invalidate {reason}; GET /features. Prefix all features paths /api/v1/swarm. Feature info includes id,title,intent,session_id,status,revision,spec,approval_digest,approved_digest,budget,profiles,base_shas,blocker. Persist spec immutable revisions and approval hash; status draft/specifying/planned/approved/running/blocked/review/mr_ready. Spec update revokes approval. Use canonical SwarmService.create_session for features. Product messages durable; POST records user message only, NEVER pretend model replied. Add methods prepare(feature_id, *, spec, plan_revision, base_shas, profiles, budget)->feature, approve, invalidate, get_feature, list_features, add_message/list_messages. prepare records immutable binding including registry hash and plan revision. Main adds orchestration wiring. No model calls/publication here. Add concurrency CAS so stale approval fails. Tables own product state, no destructive old-session migration. Router registration main-owned.

## Task 3: Controlled MR publishing primitives
Owned: whilly/swarm/publication.py (new), tests/unit/test_swarm_publication.py.
Pure trusted publication policy + injectable GitLab transport implementation. Explicit allowlist project config remote_url, project_id, target_branch, branch_prefix, ci_safe true, enabled true. Missing any yields named publication_unavailable/policy_blocked. Refuse protected target writes, force push, remote mismatch, non-swarm source branch, dirty/unverified HEAD. Candidate fields feature_id,project,repo_path,branch,base_sha,head_sha,approved_digest,verified_sha,review_approved. Plan approval identity checked. One MR per feature/project branch: query existing before create; create Draft until pipeline for exact SHA succeeds; no pipeline/missing checks stays draft, failed stays blocked. Never merge/deploy. Commands argv only and injectable runner/HTTP client; do not run external operations in tests. Export Publisher.publish(candidate,policy) -> structured outcome with mr_url,status,blocker; explicit configuration/credentials injected, never serialized. Do not edit registry/runtime. Main wires persistence/API gate later. Document adapter requirements in module.

## Task 4: Product cockpit UI
Owned: whilly/api/templates/product_swarm.html.j2, whilly/api/static/product-swarm.js (new), focused JS tests. No router/server edits.
One main product chat, feature list/select/create, current feature status/spec text, digest-bound approval, link existing session /swarm for task/Gantt. Consume Task2 endpoints; use safe textContent, visible errors, no credentials/client arbitrary paths. POST message saves intent; show explicit message that planning only runs via separate action until main wires /features/{id}/plan. Include plan button POST /features/{id}/plan {text,planner_profile}; profile select 'planner-strong'/'planner-escalation' (main may adapt), run button POST /features/{id}/run {workers}; budget inputs max_calls,max_elapsed_seconds default60/7200, save via POST /features/{id}/budget. Do not invent model answers or mark done without server. Empty/missing strong profile state visible. Mobile responsive. Product UI route /swarm/product mounted main.

## Task 5: Integrate planning, BMAD and execution gates
Main owns runtime.py, agent.py, swarm_ui.py, transport/server.py and product_workflow.py (new), model admission gate, docs/specs. Wire product chat to strong planner with feature-separated history, profile-resolved models and trusted context snapshots. BMAD adapter discovers explicit configured skill roots and their references/customization, writes only artifact workspace via controlled mode; missing skill named blocked. No whole-repo model write during planning. Bind spec/plan/model/base/limits on approval. Routes plan/budget/run reject stale approvals. Durable global model-call admission max5; budgets count all feature calls, time bound and unknown cost explicit. Stop/resume and changed requirements fail closed. Legacy sessions kept available; no automatic conversion or execution. Publisher uses only configured allowlisted targets; backend returns setup blocker otherwise. Independent review and cross-project readiness required.

## Task 6: Verification and rollout
Add OpenSpec delta and archive after passed checks. Test migrations against disposable database, concurrent approval/run/global capacity, cheap-vs-strong routing, interrupted recovery, no duplicate MR, auth/CSRF. Browser test product creation/messages/spec/approval/error states, desktop/mobile; fake two-repo canary for execution flow and adapter tests, then real target canary only with explicit target credentials. Keep unverified real-model/MR evidence honest. Enable local product UI only after checks; do not run business project tasks. Report configured vs blocked features separately.
